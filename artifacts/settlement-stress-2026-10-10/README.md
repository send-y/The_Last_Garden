# Settlement stress evidence, 2026-10-10

[Описание сценария, метода и выводов](../../docs/implementation/settlement-stress-2026-10-10.md).

Достоверные графические прогоны перечислены в `runs.json` (девять выполненных
прогонов). Для каждого имени есть JSON, UTF-8 журнал, CSV интервалов кадров
и PNG обзора. `summary.json` и `performance-comparison.png` построены из этих данных.
Поле `passed` в `runs.json` означает успешное выполнение измерителя без ошибок
движка, **не выполнение цели 100 FPS**.

`*-progress.json` показывает последний завершённый шаг; завершённый JSON содержит
все измеренные шаги и максимумы. В первых прогонах последний интервал, превышающий
запрошенную длительность, включён в статистику JSON, но отсутствует в CSV.
Сохранение этого интервала в CSV исправлено в измерителе после замеров; цифры JSON
и таблица отчёта от этого не менялись. Измеритель использует часы без пакетного
наверстывания; подробности и ограничения есть в отчёте.

`red.log` — ожидаемое первоначальное падение нового теста до реализации.
`smoke.json`/`smoke-frames.csv` — ранняя headless-проверка до исправления размещения
склада; их **нельзя использовать для FPS или выводов о готовом сценарии**.
`import.log` — промежуточный импорт. Старые журналы сохраняются как история,
а свежие функциональные результаты — `checks.json`, `rules.log`, `stress-ui.log`,
`core.log`, `lab-dialogue.log`, `home-production.log`.

Скрипты запуска принимают `--godot` с путём к локальному движку:

```powershell
python artifacts/settlement-stress-2026-10-10/run_profiles.py --godot '<Godot console.exe>' full-30
python artifacts/settlement-stress-2026-10-10/run_checks.py --godot '<Godot console.exe>'
python artifacts/settlement-stress-2026-10-10/plot_results.py
```

Проверки и графические замеры нужно запускать **раздельно**. Прогоны измерителя
идут последовательно. Headless-проверки могут выполняться по две одновременно,
их длительности не являются показателями производительности игры.
