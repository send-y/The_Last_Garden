# CPU diagnostic evidence — 2026-10-10

[Результаты, причины и порядок исправлений](../../docs/implementation/settlement-diagnostic-2026-10-10.md).

Каждая папка содержит:

- `stages.json`: прошедшее время участков, вложенные таймеры, количество вызовов,
  собственное и полное время. Полные времена вложенных функций нельзя складывать
  с временем родителя — получится двойной учёт.
- `cpu.json`: PID, нативный ID первичного потока из Windows CreateProcess,
  CPU-время процесса/потоков между синхронизированными границами. ID потока Godot
  в `boundary.json` — другая система идентификаторов; она не подставляется вместо
  Windows TID. PID из Godot сверяется с PID запущенного процесса.
- `samples.json`: периодические снимки загрузки процесса, главного потока,
  всей машины и RSS. В них входит подготовка карты и короткие handshake-паузы.
- `godot.log`: журнал движка. `boundary.json` и `ack-*` — служебные файлы
  последнего прогона, не сохранения игрока.

Прогоны: `work-30` (две минуты), `sleep-30` (одна минута), `work-3` на той же
карте 30 домов, `work-30-no-trace` с выключенными таймерами, `frames-30-settled`
с контрольными изменениями видимости/обновления сцены и `storage-redraw-30`
с дополнительными таймерами складских запросов.

`frames-30` — предварительный контроль до добавления времени на завершение
перерисовок, вызванных изменением видимости. Его последний участок включает
такую перерисовку; для сравнения неподвижной сцены используются результаты
`frames-30-settled`. `runs.json` сохраняет все семь успешных диагностических
прогонов; `passed` означает завершение измерителя без ошибок, не достижение 100 FPS.

`summary.json` / `diagnostic-comparison.png` строятся скриптом `analyze.py`.
Функциональные проверки — отдельный `checks.json` и журналы `*-ui.log`,
`trace-contract.log`, `core.log`. Их длительности не используются для FPS.

Из корня проекта на Windows, с Python 3.11, psutil 7.2.2 и matplotlib:

```powershell
python artifacts/settlement-diagnostic-2026-10-10/run_diagnostics.py --godot 'D:/Godot_v4.7-stable_mono_win64/Godot_v4.7-stable_mono_win64.exe' work-30 sleep-30 work-3 work-30-no-trace frames-30-settled storage-redraw-30
python artifacts/settlement-diagnostic-2026-10-10/analyze.py
python artifacts/settlement-diagnostic-2026-10-10/run_checks.py --godot 'D:/Godot_v4.7-stable_mono_win64/Godot_v4.7-stable_mono_win64_console.exe'
```

Для CPU-измерителя нужен **основной графический `.exe`**, без console-launcher:
так получают ID настоящего первичного потока игры. Проверки запускаются через
console `.exe`. Диагностическая сцена предназначена для запуска измерителем,
а не F6: без внешнего счётчика она завершится с сообщением об отсутствии sampler.
Не запускайте тесты параллельно графическим измерениям. Игровые прогоны строго
последовательные. Headless-проверки выполняются по две одновременно после них.

CPU-время имеет дискретность Windows-счётчиков; короткие участки и показатели
трёхсекундных кадровых окон не заменяют длинный плейтест. GPU-время, загрузка GPU,
аппаратные счётчики cache misses и привязка к конкретным ядрам не измерены.
