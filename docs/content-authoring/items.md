# Добавление предметов, еды и вариантов инструментов

Каталог: `game/content/core/items.json`. Текущий формат предметов —
`schema_version: 5`, формат пищевых свойств — `food_schema_version: 1`,
формат инструментов — `tool_schema_version: 1`.
Это версии данных контента, а не игрового сохранения (оно остаётся версии 36).

## Размер изображения и клеток

`icon_path` может указывать на подробный прозрачный PNG: размер файла не
ограничен 32×32. Клетка рюкзака и склада — 64×64 логических пикселя, клетка
мира — 32. `footprint` задаёт занимаемые клетки и не зависит от разрешения PNG.
Иконка вписывается с сохранением пропорций, в том числе при повороте и переносе.
Габарит инструмента в руках настраивается отдельно от инвентаря.

Хранить исходник с прозрачностью, небольшими полями и пропорциями, подходящими
его footprint; большой пустой фон уменьшит видимую часть инструмента.
Отрисовка ближайшим соседом сохраняет резкие края, но уменьшение подробного
изображения всё равно может скрывать мелкие детали. Проверять результат в игре.
[Текущий пилот с топором и скриншотами](../art/inventory-scale-pilot-2026-10-12.md).

## Минимальный съедобный предмет

Добавить запись в массив `items` существующего каталога:

```json
{
  "id": "example:ration",
  "label_key": "item.example.ration.name",
  "icon_path": "res://assets/sprites/items/berry.png",
  "max_stack": 5,
  "footprint": [[0, 0]],
  "food": {"satiety": 17, "energy": 0}
}
```

Иконка в примере существующая и временная. Для собственного рисунка указать
путь к существующему ассету. Ключ названия добавить в
`game/localization/core.csv`, сохраняя прежние столбцы языков и UTF-8;
переводы `.translation` создаёт импортёр Godot. Убедиться, что ID уникален.
Повторный ID вызывает ошибку с файлом и ID; такой каталог не загружается.

Сама запись не выдаёт предмет игроку и не добавляет источник появления:
получение через существующий рецепт, добычу или отдельный лабораторный сценарий
настраивается отдельно. В обычной игре тестовый `test:ration` не существует.
Этот предмет определён только в `game/tests/fixtures/item_food_additions.json`.

## Правила `food`

Оба поля `satiety` и `energy` обязательны. Значения — целые конечные числа
от 0 до 100 включительно; хотя бы одно положительно. Энергия может быть 0:
еда будет восстанавливать только сытость. Выспанность еда не восстанавливает.
При отсутствии `food` предмет не съедобен. Пустой объект, строка, отрицательное,
дробное значение и опечатка вроде `energi` дают ошибку с файлом, ID и полем.

`FirstNightContent.item_food_profile(id)` возвращает отдельный словарь
пищевой ценности либо `{}`. Питание игрока и NPC, список еды за столом,
карточка обеспеченности и меню инвентаря читают эти же определения.
Свойства подготовлены при загрузке: запрос не перечитывает JSON.

Каталог старого формата 3 может загружаться без `food`. Для пищевых свойств
нужны формат предметов 4 и формат еды 1. Неизвестные версии отвергаются.
Порча, качество или вкусовые предпочтения пока не реализованы: простое
добавление такого ключа не создаёт механику. Следующее расширение должно
явно обновить пищевую схему, её валидатор и потребителей.

## Еда, культуры и семена

`items.json` хранит пищевые значения. `crops.json` хранит рост, урожай и
связи `seed_id`/`product_id`. Для продукта новой культуры отдельно указать
`food` у соответствующего предмета, если он должен быть съедобен.
Свойство `food` само по себе не разрешает извлечение семян.

Текущие правила извлечения:

- Особые ягоды: случайная культура начального набора, 2–4 семени, без изучения.
- Продукт культуры: только её собственные семена, 1–5, после изучения.
- Остальная еда и сами семена: извлечение недоступно.

Проверка семян выполняется командой симуляции, а не только кнопкой.
Неуспешное извлечение не расходует продукт и не продвигает RNG.
Доступность семян не зависит от того, указан ли у продукта `food`.

Прежние пары сытости/энергии закреплены буквальными числами в тесте:
ягоды 14/5, морковь 28/12, капуста 45/25, картофель 30/10, клубника 20/8.
Изменение этих пар — отдельное осознанное изменение баланса.

## Границы текущего этапа

Размеры, стаки, перенос и физические экземпляры сохраняют прежние правила.
Варианты существующих инструментов работают через возможности, описанные ниже.
Новая механика требует отдельного обработчика; JSON не является языком команд.

Технический долг: `FirstNightContent` обслуживает уже общий каталог мира.
Его переименование и разделение старых стартовых данных от каталога
предметов отложены, чтобы не расширять текущий перенос пищевых свойств.

## Варианты инструментов

Если ссылки культуры становятся неактивными из-за `deprecated`, уже посаженная
культура сохраняется в сейве и отображается, но её рост/урожай приостановлены.
Новые посевы и извлечение семян такого источника запрещены. Отключённый рецепт
отменяет сохранённый проект, возвращая его известные зарезервированные материалы
дропами у станции; повторная загрузка не повторяет возврат.

Для нового топора добавить запись с уникальным ID, локализацией и ассетом:

```json
{
  "id": "example:axe",
  "label_key": "item.example.axe.name",
  "icon_path": "res://assets/sprites/items/axe_n.png",
  "instance_based": true,
  "max_stack": 1,
  "footprint": [[0, 0], [1, 0], [0, 1], [1, 1], [0, 2]],
  "tool": {"actions": ["chop", "clear_bush"], "grip": "shaft"}
}
```

Для своего ассета изменить `icon_path`; форму клеток выбрать под рисунок.
Чтобы получить этот предмет, отдельно добавить действующий источник, например
выход существующего рецепта. Одно определение в каталоге не создаёт предмет.

Поддерживаются ровно четыре набора действий; порядок внутри набора неважен:

| Модель механики | `actions` | `grip` | Дополнительное поле |
|---|---|---|---|
| Топор | `["chop", "clear_bush"]` | `shaft` | Нет |
| Кирка | `["mine"]` | `shaft` | Нет |
| Мотыга | `["till"]` | `shaft` | Нет |
| Ведро | `["water"]` | `carry` | `water_capacity`: целое 1–16 |

`tool` необязателен. При его наличии обязательны `instance_based: true`,
`max_stack: 1`, правильные действия и хват. Неизвестные поля, дубликаты действий,
неподдерживаемые комбинации и неверные типы дают ошибку с файлом, ID и полем.
Неисправное определение не получает возможности. Форматы 3/4 по-прежнему
читаются по своим правилам, но не допускают новые `tool` и `deprecated`.

Для ведра на четыре полива профиль и иконки состояния выглядят так:

```json
"tool": {"actions": ["water"], "grip": "carry", "water_capacity": 4},
"icon_state_property": "charges",
"icon_state_paths": {
  "0": "res://assets/sprites/items/bucket_not_full.png",
  "1": "res://assets/sprites/items/bucket_full.png",
  "2": "res://assets/sprites/items/bucket_full.png",
  "3": "res://assets/sprites/items/bucket_full.png",
  "4": "res://assets/sprites/items/bucket_full.png"
}
```

Это фрагмент записи предмета, а не отдельный JSON-файл. `icon_state_paths`
сопоставляет точные значения; отдельные рисунки для промежуточных состояний
можно добавить позже. Правила иконок по доле заполнения ещё нет.

Симуляция требует выбранный физический экземпляр игрока или экземпляр,
принадлежащий работающему NPC. Наличие в рюкзаке/на складе или один `charges`
у обычного предмета не разрешают действие. Смена экземпляра, даже на другую
копию той же модели, прерывает начатую добычу. У каждого ведра своя вода.
NPC выбирает первый доступный совместимый инструмент по порядку склада;
сравнения качества или ёмкости пока нет. Мотыга не добавляет NPC новую работу.

`state.charges` — универсальные целочисленные заряды экземпляра. Для воды
один заряд означает один полив; наполнение восстанавливает ёмкость модели.
При создании и загрузке водного инструмента неверный тип, дробь, NaN/INF или
отсутствующее значение становятся 0; целое ограничивается 0…ёмкость.
Прочие поля состояния сохраняются. Состояние неводного предмета не трактуется
как вода. Числа обычной игры прежние: ведро 2, расход 1, влага 1440 минут.

## Устаревшие определения и источники

Опубликованный ID не переименовывать и не удалять. Сохранить определение,
локализацию и ассеты и добавить `"deprecated": true` (строго bool).
Существующий экземпляр, выбранный предмет и инструмент в работе NPC продолжают
работать. Это не механизм замены ID или миграции модели.

Новые источники не могут ссылаться на неизвестные или устаревшие определения:

- `recipes.json`: ключи предметов в `inputs` и `outputs`;
- `first_night_objects.json`: `collect_rules.*.item_id`;
- `crops.json`: `seed_id` и `product_id`;
- встроенная стартовая кладовая и дроп шишки.

Проверка выполняется до активации источника. Неисправная запись отключается,
диагностика содержит путь, владельца, поле и ID; в лог пишется предупреждение.
Если все культуры отключены, извлечение семян отказывает без расхода ягод/RNG.
Обычного загрузчика произвольных пулов ещё нет. Будущий загрузчик должен
перед активацией вызывать `validate_item_references` для своих записей;
добавление поля `pool` в произвольный JSON сейчас не создаст спавн.

`FirstNightContent` предоставляет `item_tool_supports`, `item_tool_capacity`,
`item_tool_grip`, `item_is_deprecated` и изолированный `item_tool_profile`.
Горячие проверки читают подготовленные значения, не перечитывают JSON.
WorldSimulation, крафт и фермерство принимают один каталог до нормализации.
UI и персонажи читают действующий каталог симуляции, включая после reload.

Если из сейва всё же исчезает неизвестный физический предмет, нормализация
выдаёт структурированную диагностику. `get_item_load_diagnostics()` возвращает
отдельный массив строк `{id, count, reason}`; `count` — число физических записей,
причины — `unknown_item_definition` либо `not_instance_based`.
Массив очищается перед очередной нормализацией и не пишется в сейв.
Лог печатает те же строки; это предупреждение не восстанавливает пропавший ID.

Проверенные примеры вариантов находятся только в
`game/tests/fixtures/item_tool_additions.json`; в обычную игру они не добавлены.
Результаты и ограничения: [отчёт](../implementation/item-tool-variants-2026-10-11.md).
