# Технический план 2A: присутствие первого NPC

- **Техническая реализация:** завершена и слита в `main` через PR #3 28 июля 2026 года.
- **Автоматическая проверка:** пройдена.
- **Ручной плейтест появления и взаимодействия:** не зафиксирован.
- **Переход к 2B:** открыт после слияния checkpoint L2 через PR #5 28 июля 2026 года.

Цель этого шага — проверить минимальную цепочку «в мире появляется самостоятельный человек», не добавляя пока полноценную социальную симуляцию.

## Что входит

- Первый NPC описан данными в `game/content/core/npcs.json`.
- NPC скрыт до завершения первой ночи.
- После сна NPC появляется рядом с Общим домом.
- NPC не появляется в одной точке с игроком.
- До первого разговора NPC отображается как неизвестный путник.
- После первого разговора NPC становится известен по имени.
- Внешность генерируется от стабильного seed и сохраняется в состоянии.
- NPC можно выбрать мышью как обычный interactable и выполнить действие.
- Состояние NPC сохраняется и восстанавливается через save/load.
- Симуляция получает ID участника, цели и действия, сама определяет тип цели и проверяет существование, видимость и расстояние.
- Запросы состояния возвращают изолированные снимки, а не изменяемые словари симуляции.

## Что намеренно не входит

- потребности NPC;
- расписание и автономный выбор работы;
- просьбы, согласие, отказ и обязательства;
- модель доверия, тепла и уважения;
- свободный текстовый диалог;
- pathfinding и самостоятельное перемещение.

Потребности, движение и распорядок относятся к 2B; работа и структурированные просьбы — к 2C; память, отношения и контекстная реплика — к 2D. Свободный текст и генеративная модель остаются срезом 7.

## Структура реализации

- `game/content/core/npcs.json` — контентные определения NPC.
- `game/src/characters/npc_catalog.gd` — загрузка определений, создание начального состояния, нормализация save-данных и простая логика разговора.
- `game/src/characters/character_appearance.gd` — seed-based выбор модульной внешности.
- `game/src/characters/character_visual.gd` — отрисовка персонажа примитивными слоями.
- `game/src/simulation/first_night_simulation.gd` — состояние NPC, активация после первой ночи и обработка взаимодействия.
- `game/src/save/first_night_save_store.gd` — временный файл, резервная копия и восстановление после повреждённого JSON.
- `game/src/world/first_night_catalog.gd` — регистрация NPC как interactable.
- `game/src/world/interactable_view.gd` — отображение NPC через `CharacterVisual`.

## Формат сохранения

С версии save `3` состояние NPC хранится в `npcs`.

Минимальный формат для первого NPC:

```json
{
  "npcs": {
    "core:first_neighbor": {
      "id": "core:first_neighbor",
      "active": true,
      "known": false,
      "talk_count": 0,
      "position": [848.0, 944.0],
      "appearance_seed": 13346,
      "appearance": {}
    }
  }
}
```

`appearance` в реальном сохранении содержит выбранные ID частей внешности. Если сохранение старое или внешность повреждена, она пересобирается от `appearance_seed`. Неизвестные словари NPC сохраняются для будущего контента, а некорректные вложенные значения не должны ломать загрузку.

## Проверка

Автоматические проверки подтверждают:

- новый save создаёт скрытого NPC;
- после завершения первой ночи NPC активируется;
- NPC не появляется внутри игрока;
- первый разговор открывает имя;
- цель игрока после первой ночи указывает на нового путника;
- save/load сохраняет активность, известность имени и внешность NPC;
- поддельный участник, действие, цель и взаимодействие на расстоянии отклоняются;
- снимки состояния нельзя использовать для обхода симуляции;
- повреждённые вложенные данные нормализуются, будущая версия отклоняется;
- основной и резервный файлы сохранения ротируются и читаются.

Ручной плейтест должен отдельно ответить:

- заметно ли прибытие путника утром;
- не возникает ли NPC внутри игрока или другого объекта;
- понятно ли, как выбрать путника и начать разговор;
- создаёт ли короткая сцена ощущение появления самостоятельного человека, а не нового интерфейсного юнита.
