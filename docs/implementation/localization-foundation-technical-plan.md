# Технический план L2: фундамент локализации

## Статус

- **Checkpoint:** Infrastructure L2 перед 2B.
- **Рабочая ветка:** `codex/localization-foundation`.
- **Реализация:** технически завершена в рабочей ветке.
- **Автоматическая проверка:** пройдена.
- **Ручная проверка русских строк в основной сцене:** не зафиксирована.
- **Слияние и открытие 2B:** не выполнены.

## Зачем L2 появился сейчас

У первого среза уже есть HUD, объекты, предметы, цели, системные ошибки и реплики NPC. Если оставить готовый русский текст внутри симуляции и JSON, последующее добавление языков потребует менять не только контент, но и команды, тесты и сохранения.

L2 вводит границу до расширения NPC-систем:

```text
симуляция и данные -> стабильный ключ + параметры
Session / HUD      -> перевод ключа -> видимая игроку строка
```

Симуляция остаётся источником игрового результата, но больше не выбирает язык его отображения.

## Принятый формат

### Каталог перевода

Базовый каталог находится в `game/localization/core.csv`.

- первый столбец содержит уникальные смысловые ключи;
- столбец `ru` содержит исходный русский текст;
- CSV хранится в UTF-8 без BOM;
- русский язык является fallback проекта;
- импортируемый `.translation` создаётся Godot и не является исходным файлом;
- новые языки позднее добавляются отдельными столбцами без изменения игровых ID.

CSV выбран для раннего объёма контента как наиболее простой встроенный формат Godot. Переход на PO допускается позднее с сохранением тех же ключей, если появятся внешние переводчики или большой объём многострочных диалогов.

Основание: [локализация через CSV в Godot 4.7](https://docs.godotengine.org/en/4.7/tutorials/i18n/localization_using_spreadsheets.html) и [общие правила интернационализации](https://docs.godotengine.org/en/4.7/tutorials/i18n/internationalizing_games.html).

### Имена ключей

Ключ описывает смысл и область применения, а не повторяет текст:

```text
ui.hud.objective
item.core.wood.name
object.core.common_house.name
first_night.failure.repair.tools_required
npc.core.first_neighbor.name
dialogue.core.first_neighbor.greeting
```

Редактирование русской формулировки не должно требовать переименования ключа.

### Контентные данные

Схемы пяти JSON-файлов подняты до версии 2. Видимые строки заменены ссылками:

- `label_key`;
- `message_key`, `full_message_key`, `empty_message_key`;
- `message_keys`, `failure_message_keys`, `stage_label_keys`;
- `name_key`, `unknown_label_key`, `greeting_key`, `repeat_line_key`.

Технические ID вида `core:wood` и ключ перевода выполняют разные задачи. ID связывает игровые системы и сохранения, а ключ выбирает отображаемый текст.

## Контракт результата симуляции

Результат команды больше не содержит готовое поле `message`:

```gdscript
{
    "type": "command_result",
    "success": false,
    "message_key": "interaction.failure.too_far",
    "message_args": {},
    "changed": false,
    "auto_save": false,
}
```

Именованные параметры разрешают переводчику менять порядок частей предложения. Для реплики NPC имя и строка передаются отдельными вложенными ссылками, после чего `LocalizedText` собирает видимое сообщение на границе представления.

Debug-интерфейс лаборатории может временно использовать буквальные строки через `Session.notify_player()`. Игровой интерфейс использует `notify_player_key()`. Технические `push_error()`, имена файлов и диагностические коды не относятся к локализуемому контенту.

## Структурированный выбор в мире

До L2 HUD определял клетку по русскому префиксу `Клетка`. Теперь мир передаёт словарь одного из трёх типов:

- `none`;
- `cell` с координатами;
- `interactable` с подписью и признаком доступной дистанции.

Логика интерфейса больше не зависит от конкретной формулировки перевода.

## Save v4

В save v3 поле `outcomes` содержало готовые русские фразы. Save v4 хранит только стабильные ID:

| Save v1–v3 | Save v4 |
|---|---|
| `сухая комната` | `core:dry_room` |
| `холодный сквозняк` | `core:cold_draft` |
| `остаточное тепло` | `core:residual_warmth` |
| `безопасная вода` | `core:safe_water` |
| `лёгкий ужин` | `core:light_supper` |
| `голодный сон` | `core:hungry_sleep` |

Точные русские значения остаются в коде только как отпечатки старого формата. При загрузке версий 1–3 они преобразуются в ID. Уже namespaced-значения, включая `mod:*`, сохраняются; неизвестные старые строки отбрасываются.

Итог утра локализуется только при показе, поэтому смена языка не изменяет постоянное состояние мира.

## Проверки

Автоматический набор подтверждает:

- импорт и разрешение русского каталога;
- именованные и вложенные параметры;
- отсутствие дубликатов ключей;
- наличие каждого ключа, на который ссылаются рабочие GDScript- и JSON-файлы;
- возврат ключей вместо русского текста из симуляции;
- миграцию всех шести исходов v3 в save v4;
- JSON round-trip стабильных outcome ID;
- прежние правила первой ночи, NPC, сохранения и Mechanics Lab.

Команды из корня репозитория:

```powershell
godot --headless --editor --path game --quit
godot --headless --path game --script res://tests/run_tests.gd
godot --headless --path game --quit-after 3
godot --headless --path game res://src/dev/mechanics_lab.tscn --quit-after 3 -- --lab-scenario=fresh_start
godot --headless --path game res://src/dev/mechanics_lab.tscn --quit-after 3 -- --lab-scenario=prepared_evening
godot --headless --path game res://src/dev/mechanics_lab.tscn --quit-after 3 -- --lab-scenario=morning_with_mira
```

## Не входит в L2

- английский, украинский и другие готовые переводы;
- меню выбора языка и отдельный файл пользовательских настроек;
- перевод debug-панели Mechanics Lab;
- полноценная система множественных форм;
- locale-aware форматирование списков, чисел, дат и единиц измерения;
- локализация изображений, звука и названия приложения.

Эти задачи добавляются только когда появится реальная потребность. L2 создаёт для них устойчивую границу, но не раздувает текущий срез.

## Критерии перехода

Checkpoint готов к слиянию, когда:

1. Все автоматические проверки проходят.
2. Основная сцена и три сценария Mechanics Lab загружаются без ошибок.
3. Игрок вручную видит прежний русский интерфейс, цели, взаимодействия и реплику Миры.
4. После отдельного подтверждения ветка L2 слита.

Только после этого можно отдельно открыть 2B.
