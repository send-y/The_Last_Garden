# Загрузка WorldSimulation при устаревшем реестре классов

На скриншоте редактора Godot — каскад `Could not find type WorldSimulation`
в Session и тестах, затем ошибки вывода типов переменных.

Обычный запуск новой копии процесса проходит на Godot 4.7 Standard и
установленной у автора версии Mono. В изолированной копии проекта удаление
только регистрации WorldSimulation из кэша глобальных классов воспроизвело
280 ошибок компиляции. Это подтверждает зависимость от регистрации класса;
устаревший реестр открытого редактора — объяснение исходного скриншота,
которое нельзя проверить напрямую по самому изображению.

Session, Mechanics Lab и тесты теперь используют тип явно загруженного
скрипта (`Simulation` или `World` через `preload`). Типизация сохранена.
Глобальное имя WorldSimulation остаётся доступным после обычного импорта.
Кэш реального проекта и пользовательские сохранения не изменяются исправлением.

После изменения та же изолированная проверка компиляции проходит с нулём
ошибок. Повторяемая регрессия: `game/tests/check_world_class_registry.py`,
параметр `--godot` принимает путь к исполняемому файлу Godot. Журналы:
`artifacts/world-class-loading-2026-10-08`.

Итог: пять проверок с отсутствующей глобальной регистрацией прошли;
основной набор тестов, постоянный мир, его интеграция с интерфейсом и UI
помощи NPC прошли повторно. Графический тест выполнен на установленной
Mono-версии Godot 4.7, ошибок нет. `git diff --check` также прошёл.

Уже показанные ошибки в панели редактора могут оставаться историей прежнего
запуска. После обновления файлов нужно повторно запустить проект; если редактор
продолжает показывать старую ошибку, сохранить открытые изменения и перезапустить
Godot с `game/project.godot`.
