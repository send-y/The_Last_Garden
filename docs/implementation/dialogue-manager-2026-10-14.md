# Dialogue Manager: вывод для пакета D

Официальные источники прочитаны 14 октября 2026; зависимость не устанавливалась.

1. **Godot 4.7 Mono и лицензия.** Ветка Dialogue Manager 4 заявляет Godot 4.6+;
   есть C# wrapper, лицензия MIT. Следовательно, версия 4.7 Mono укладывается
   в заявленные требования. Запуск с нашим проектом не проверен.
   [README](https://github.com/nathanhoad/godot_dialogue_manager),
   [C#](https://github.com/nathanhoad/godot_dialogue_manager/blob/main/docs/CSharp.md),
   [лицензия](https://github.com/nathanhoad/godot_dialogue_manager/blob/main/LICENSE).
2. **Симуляция остаётся источником истины.** Runtime stateless; читает свойства
   и вызывает методы игры. Для нашей интеграции нужен узкий посредник:
   запросы фактов и команды симуляции с повторной проверкой условий.
   Прямой доступ диалога к живым словарям исключаем своей архитектурой;
   плагин сам это не гарантирует.
   [State](https://github.com/nathanhoad/godot_dialogue_manager/blob/main/docs/State.md).
3. **Локализация.** Поддерживаются статические ID строк и CSV/PO. Семантические
   ключи могут быть ID; переход требует явного соответствия нашим ключам
   и аргументам. Автоматической совместимости всей текущей схемы нет.
   [Translations](https://github.com/nathanhoad/godot_dialogue_manager/blob/main/docs/Translations.md).
4. **Сейв.** Stateless runtime не требует своего игрового формата сохранения.
   Наши факты встречи/подарка можно хранить в существующих словарях NPC.
   Проверка нормализации, миграции и одноразовых последствий остаётся нашей.
   Это вывод из модели состояния, не проверка установленного плагина.
5. **Расширяемые разговоры.** Плагин даёт редактор, ветки, условия и выполнение
   реплик; он не заменяет каталоги намерений, знания/память жителей и игровые
   последствия. Полезен при большом объёме авторских сцен и необходимости
   визуального редактирования. Для одной встречи сохраняем текущие данные/HUD.

**Рекомендация:** пакет D реализовать без новой зависимости. Вернуться к выбору
редактора при существенном росте авторских диалогов. Сравнение Yarn/Ink отдельно
не выполнялось; цифра «сотни реплик» — ориентир автора, не технический предел.
