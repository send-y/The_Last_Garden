# Свойства предметов: еда — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавлять еду вне системы культур через данные, с одинаковыми
свойствами и корректным расходом у игрока и NPC.

**Architecture:** `FirstNightContent` хранит пищевую ценность предмета;
симуляция и UI читают один подготовленный каталог. `CropCatalog` хранит
выращивание и связь продукта с семенем. Извлечение семян не следует из
съедобности. Никакой новый предмет не добавляется в обычный старт.

**Tech Stack:** Godot 4.7, GDScript, JSON, Windows/PowerShell.

**Spec:** [Утверждённое направление и дизайн](../specs/2026-10-10-content-extensibility-design.md).

Варианты инструментов остаются следующим результатом части предметов;

## Global Constraints

- Пищевая ценность: `satiety` и `energy`; отсутствие свойства означает,
  что предмет не съедобен.
- Исходные параметры еды переносим без изменения чисел.
- Связи культуры с семенем и продуктом остаются в `crops.json`.
- Проверка выбранного физического экземпляра и его состояния остаётся обязательной.
- Новая механика всё ещё требует отдельного обработчика в коде.
- Каталоги загружаются и проверяются один раз при подготовке контента.
- Примеры сначала живут в тестовых каталогах или лабораторном сценарии.
- Не меняем формат save 36, профиль персонажей, минутную частоту или карту.
- До реализации создаём локальный коммит накопленной работы по прямому
  запросу автора 11 октября; исключаем `__pycache__`, пуш не выполняем.
  Новую реализацию оставляем отдельным diff поверх этой контрольной точки.
- Не запускаем новые стресс-замеры/FPS-прогоны. Предлагаемые ниже проверки —
  только корректность нового контракта; до просмотра плана они не запускаются.

## Review Focus

1. Съедобный предмет вне культур: работает в рюкзаке, у NPC и за столом,
   но не получает кнопку/команду извлечения семян.
2. Еда с нулевой энергией и положительной сытостью: съедобна; полностью
   нулевая, отрицательная, бесконечная или неверно типизированная еда отвергается.
3. Закрытый доступ к извлечению семян: продукт культуры съедобен, а извлечение
   остаётся недоступным; отказ не расходует предмет и не меняет RNG.
4. Ужин перед сном и предпросмотр сна: оба используют прежние значения ягод,
   чтобы перенос свойств не изменил результат ночлега.
5. Независимость возвращённого словаря и повторного чтения: вызывающий код
   не мутирует определения; горячие запросы не перечитывают JSON.

Уточнения по ревью автора: неизвестный ключ внутри `food` — ошибка с ID и
полем; оба поля обязательны. Нормативные пять пар проверяются буквальными
числами в тесте, независимо от каталога культур. Каталог предметов получает
`schema_version: 4`, `food_schema_version: 1`; следующая версия пищевых полей
требует явного обновления поддерживаемой схемы. Старый формат предметов 3
принимается без `food`; новое свойство в нём отвергается как ошибка формата.
Переименование `FirstNightContent` записывается как долг, не выполняется здесь.

## Файлы и интерфейсы

Изменить:

- `game/src/content/first_night_content.gd`: запрос и проверка пищевых свойств.
- `game/content/core/items.json`: необязательный `food` у съедобных предметов.
- `game/content/core/crops.json`: убрать дубли пищевых значений после перевода потребителей.
- `game/src/needs/character_needs.gd`: запрос еды делегирует каталогу предметов.
- `game/src/needs/npc_food_supply.gd`, `household_feedback.gd`,
  `game/src/furniture/furniture_system.gd`: передают `sim.content`.
- `game/src/farming/farming_system.gd`: еда из предметов, отдельная проверка
  наличия извлечения семян; текущая транзакция семян сохраняется.
- `game/src/ui/inventory_panel.gd`, `farming_panel.gd`: те же определения,
  независимые кнопки еды и семян.
- `game/src/simulation/systems/world_calendar.gd`: значения предпросмотра сна.
- `game/tests/farming_integration_test.gd`: ожидаемая энергия из предмета.

Создать:

- `game/tests/item_food_properties_test.gd` и локальные тестовые данные.
- `game/tests/item_food_actions_test.gd`: команды, NPC и доступность действий.
- `docs/content-authoring/items.md`: минимальный пример и ограничения.

Производимые интерфейсы:

- `FirstNightContent.item_food_profile(item_id: String) -> Dictionary`:
  `{ "satiety": int, "energy": int }` или `{}`; возвращает отдельный словарь.
- `FirstNightContent.validate_item_food(item: Dictionary) -> Array[String]`:
  отсутствие `food` допустимо; присутствующие значения — целые конечные
  числа 0–100 включительно, хотя бы одно положительно. `satiety` и `energy`
  обязательны, неизвестные ключи отвергаются. Ошибка содержит ID и поле.
- `FirstNightContent.validate_item_schema(data: Dictionary) -> Array[String]`:
  принимает описанные версии 3/4 и пищевой формат 1; неизвестные версии
  и `food` в старом формате дают явные ошибки.
- `FirstNightContent._init(items_path: String = ITEMS_PATH)`:
  путь переопределяется только для проверки отдельных каталогов;
  штатные пути остальных данных не меняются.
- `CharacterNeeds.food_profile(item_id: String, items: FirstNightContent) -> Dictionary`:
  делегирует `items.item_food_profile(item_id)`.
- `FarmingSystem.can_extract_seeds(item_id: String) -> bool`:
  только особые ягоды или точный `product_id` культуры; наличие изучения
  проверяется отдельно через прежний `extraction_unlocked(sim)`.

## Граница следующего результата

После этого — варианты существующих инструментов через поддерживаемые
возможности, а не ID. В текущем коде отдельные проверки есть в добыче,
вспашке, выборе инструмента NPC и отображении предмета в руках; переносить
только командную проверку недостаточно. Параметры ведра и выбранный физический
экземпляр требуют отдельного контракта. Это ещё не реализовано данным планом.
