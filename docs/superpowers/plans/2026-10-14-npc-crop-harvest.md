# Сбор общего урожая жителями — план реализации

> Для исполнителя: выполнять последовательно через `superpowers:executing-plans`.
> Делегирование — только по отдельному выбору автора. Шаги отмечаются `[ ]`.

**Goal:** соединить выращивание, самостоятельный сбор NPC и физическое питание поселения.

**Architecture:** расширить FarmingSystem общим авторитетным сбором для
игрока и NPC. Использовать текущие рабочие задания, груз и склад; голодный
маршрут подключить к системе питания через тот же сбор. UI отправляет команды.

**Tech Stack:** Godot 4.7, typed GDScript, JSON-каталоги, CSV-локализация,
существующий изолированный запуск проверок.

**Spec:** [Предложенный дизайн и согласованные правила](../specs/2026-10-14-npc-crop-harvest-design.md).

**Статус:** план подготовлен 14 октября 2026 по `563f3bc`; код не изменён.
Автор согласовал общие грядки, добычу урожая при голоде и учёт семян
в отчёте без запрета еды. Остальной дизайн предложен для рассмотрения.
Запрос плана не разрешает начинать реализацию.

## Общие ограничения

- Только грядки с явным разрешением; новые поля по умолчанию выключены.
- Сон и критическое истощение выше добычи ещё не собранного урожая.
- Состояние и проверки принадлежат симуляции, урожай и груз физические.
- Сохранить баланс, культуры, старый прогресс и посторонние правки автора.
- Записывать фактические семена и расход продукции; не вводить резерв
  продукции, автоматическое извлечение или ограничение еды ради следующего посева.
- Не трогать игровой сейв/backup. Не повторять и не перезаписывать логи D.
- Локальные осмысленные коммиты; публикация не входит в задачу.

## На что обратить внимание при проверке

1. Игрок собирает или меняет растение во время подхода NPC: нет повторного урожая (задачи 1–2).
2. Два жителя одновременно добывают еду/работают на одной грядке: один сбор (задача 3).
3. Склад заполняется после выбора цели: сохраняется весь реальный продукт (задача 2).
4. Сейв после сбора, но до подбора: урожай не возникает повторно и не исчезает (задачи 2–3).
5. Голод во время сна/критического истощения: житель не уходит добывать урожай (задача 3).

## 3. Добыча урожая для голодного жителя

**Изменить:** `game/src/needs/npc_food_supply.gd`,
`game/src/npc_work/npc_crop_harvest.gd`, `npc_work_state.gd`,
`game/src/simulation/npc_autonomy.gd`.
**Создать тест:** `game/tests/npc_crop_harvest_food_test.gd`.

**Интерфейсы:**
`NpcCropHarvest.find_meal(sim, npc: Dictionary) -> Dictionary` — источник
`crop` для нынешних `NpcFoodSupply.find_meal/fulfil`;
`NpcCropHarvest.fulfil_meal(sim, npc: Dictionary, meal: Dictionary) -> bool`
делает один физический шаг приобретения, без прямого начисления сытости.
Сохраняемый `crop_food_trip` содержит `cell`, `crop_id`, `phase`, `drops`;
его нормализует `NpcWorkState.normalize`, количество продукции туда не копируется.

- [ ] Написать падающие проверки: голод без личной/складской еды и ягод;
  личная грядка; сон, критическая энергия, продолжающийся отдых; два голодных
  жителя; пересечение с обычным сборщиком; полный склад; занятый рабочий груз.
- [ ] Добавить урожай как следующий источник после действующих источников еды.
  Выбирать только съедобный продукт живого каталога и разрешённую грядку.
  Не выдавать этот источник как готовую еду для исключения `urgent_meal`.
- [ ] Реализовать подход, единый сбор, физический подбор одной единицы продукта

  существующий груз по ёмкости; защищённые предметы сверх ёмкости остаются

  При загрузке удалённые ID не восстанавливать и не повторять сбор.
- [ ] Проверить отмену обоих разрешений в пути и сейв после сбора/перед едой;

**Интерфейсы отчёта:**
`_crop_seed_snapshot(sim) -> Dictionary` в новом семидневном тесте
возвращает строки по `crop_id` из действующего каталога:
`seeds_by_location`, `products_by_location`, `living_beds`, `perennial_beds`,
`extraction_unlocked`. Места: `player`, `npc_personal`, `storage`,
`npc_cargo`, `world_drops`; каждый физический предмет учитывается один раз.
Дневная строка дополняется `seeds_planted`, `seeds_extracted`,
`products_used_for_seeds`, `products_harvested`, `products_eaten_by_actor`.
Снимки и дневные счётчики существуют только в тесте/диагностике, не в сейве.
`NpcWorkMetrics.record_harvest(sim, actor_id: String, item_id: String, amount: int) -> void`
записывает успешный физический выход при включённой диагностике;
`harvest_snapshot(day: int) -> Dictionary` возвращает счётчики по актёрам
и продуктам, аналогично существующему `food_snapshot`.

## Запуск проверок при реализации

Проверить наличие Godot 4.7 и Python. Использовать `tools/run_checks.py`:

```powershell
python tools/run_checks.py harvest-rules-red-01 npc_crop_harvest_rules_test.gd
python tools/run_checks.py harvest-rules-green-01 npc_crop_harvest_rules_test.gd farming_rules_test.gd
python tools/run_checks.py harvest-ui-green-01 graphic:npc_crop_harvest_ui_test.tscn
```

Имена прогонов должны быть новыми: runner отказывает при существующей папке.
Он сейчас пишет в `artifacts/package-d-2026-10-14/<run_id>`; это технический
путь хранения новых логов, они не являются проверками завершённого пакета D.
В итоговом отчёте перечислить точные новые пути. Runner изолирует Session,
проверяет код выхода, результат и хеши игрового сейва/backup. Новые тесты
со своим FileAccess также должны использовать отдельный временный путь.
Headless не подтверждает внешний вид: UI запускать с `graphic:` и смотреть кадры.
